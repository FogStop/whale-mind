# qqbot 共脑指南（desktop 与 QQ 里的她共用同一个大脑）

## 原理

whale-mind 的所有记忆都落在 `dataDir` 一个目录里（diary/*.jsonl + manifest + relationship + 手记.md）。
**两个 profile 只要把 `dataDir` 配成同一个路径，就是同一个大脑。**

```yaml
# desktop profile 的 cordis.patch.yml
whale-mind:
  dataDir: "C:\\Users\\<你>\\.dsh\\whale-mind"   # 可自定义；qqbot 配同一个即可
```

QQ 侧接入走腾讯官方 `@tencent-connect/dsh-qqbot` 插件（扫码绑定，无封号风险）。

## 已知边界（如实记录）

1. **多会话并发写**：feiyu §17.13 实测多会话整份重写会静默吃数据。whale-mind 采用
   **追加式 JSONL + 墓碑 manifest**，天然规避"整份覆盖"这一路径；但 manifest 本身
   仍是"后写者赢"，极端并发下删除标记可能丢失。**建议：qqbot 与 desktop 尽量不同时
   高频写入**；彻底解法（SQLite 单写者 / 三路合并）列在路线图。
2. **注入缓存按会话隔离**：desktop 与 qqbot 各自缓存各自的注入文本，但数据同源——
   QQ 里聊的新记忆，桌面下轮会话就能召回（写入后缓存失效机制保证）。
3. **性能**：索引每次加载现场重建，几千条毫秒级；两 profile 同时跑也只是双倍重建。

## AstrBot 备选路线

whale-mind 引擎与 DSH 解耦（纯 node:fs + 标准 JSONL）。若走 AstrBot + NapCat 路线，
写一个读同一 dataDir 的适配器即可复用记忆（已预留 `adapters/astrbot/` 目录）。
风险提示：NapCat 为非官方协议，有账号风控风险，不要用主号。
